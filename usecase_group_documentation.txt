I. TỔNG QUAN USE CASE - GROUP
================================================================================

GROUP là module quản lý nhóm trong mạng xã hội. Hỗ trợ:
	- Quản lý Group (CRUD)
	- Quản lý thành viên (mời, kick, rời nhóm, phân quyền)
	- Hệ thống Department/Role (chỉ group công ty)
	- Quản lý bài viết (đăng, duyệt, ghim, tìm kiếm, ảnh)
	- Bình chọn (Vote)
	- Sự kiện (Event)
	- Góp ý (Suggestion)
	- Thông báo nổi bật (MakeNotification)

Phân quyền Group (3 cấp):
	- owner: chủ sở hữu (quyền cao nhất)
	- admin: quản trị viên (được owner bổ nhiệm)
	- member: thành viên thường

III. USE CASE & SEQUENCE / ACTIVITY DIAGRAM (DẠNG TEXT)

-----[USE CASE A] QUẢN LÝ GROUP (CRUD)------------------------------------------

Chức năng:
	- Tạo group mới
	- Xem chi tiết group (kèm member_count, is_member, is_pending, my_membership)
	- Cập nhật thông tin group
	- Xóa group (chỉ owner)
	- Liệt kê group của tôi
	- Khám phá group (gợi ý group chưa tham gia)

--- A.1 TẠO GROUP (CreateGroup) ---

Use case: Người dùng tạo một nhóm mới.
Actor: User (đã xác thực)
Điều kiện: User đã đăng nhập, chưa vượt quá throttle.

Sequence diagram (text):
	User -> Frontend: Bấm "Tạo Group" -> Form hiện ra
	User -> Frontend: Điền tên, mô tả, ảnh bìa, loại (công ty/cá nhân), privacy
	Frontend -> Backend: POST /api/group/create/ (gửi JSON/form-data kèm token)
	Backend -> Permission: Kiểm tra IsAuthenticated -> Pass
	Backend -> Throttle: Kiểm tra ScopedRateThrottle('create_group') -> Pass
	Backend -> Database (transaction.atomic):
		1. serializer.save(created_by=request.user) -> Tạo Group
		2. GroupMember.objects.create(group=instance, user=request.user, role='owner')
		   -> Gán user làm owner
	Backend -> Frontend: Trả về serialized data (201 Created)
	Frontend -> User: Hiển thị group mới, chuyển hướng về trang group

--- A.2 XEM CHI TIẾT GROUP (GroupDetailView) ---

Use case: Xem thông tin chi tiết của một group.
Actor: User (đã xác thực)

Sequence diagram (text):
	User -> Frontend: Bấm vào group
	Frontend -> Backend: GET /api/group/<group_id>/detail/ (kèm token)
	Backend -> Database:
		- Lấy Group theo group_id
		- Annotate: member_count (số thành viên active)
		- Annotate: is_member (user có là thành viên active không)
		- Annotate: is_pending (user có request đang pending không)
		- Prefetch my_membership: GroupMember của user kèm job_role, department
		- select_related created_by__profile
	Backend -> Frontend: Trả về GroupSerializer data
	Frontend -> User: Hiển thị thông tin group

--- A.3 CẬP NHẬT GROUP (UpdateGroup) ---

Use case: Chỉnh sửa thông tin group (chỉ admin/owner).
Actor: Admin/Owner (đã xác thực)

Sequence diagram (text):
	User -> Frontend: Bấm "Chỉnh sửa" -> Form hiện ra với dữ liệu cũ
	User -> Frontend: Sửa tên, mô tả, privacy, is_company,...
	Frontend -> Backend: PATCH /api/group/<group_id>/update/ (kèm token)
	Backend -> Permission: IsAuthenticated -> Pass
	Backend -> Permission: IsAdminOrOwnerGroup -> Kiểm tra user có role owner/admin -> Pass
	Backend -> Database (transaction.atomic):
		1. Lấy group cũ, lưu old_is_company
		2. serializer.save() -> Cập nhật group
		3. Nếu old_is_company=True và new_is_company=False (bỏ chế độ công ty):
		   - Xóa tất cả GroupRole của group
		   - Xóa tất cả GroupDepartment của group
	Backend -> Frontend: Trả về serialized data (200 OK)
	Frontend -> User: Hiển thị thông tin đã cập nhật

--- A.4 XÓA GROUP (DeleteGroup) ---

Use case: Xóa group vĩnh viễn (chỉ owner).
Actor: Owner (đã xác thực)

Sequence diagram (text):
	User -> Frontend: Bấm "Xóa Group" -> Xác nhận
	Frontend -> Backend: DELETE /api/group/<group_id>/delete/ (kèm token)
	Backend -> Permission: IsAuthenticated -> Pass
	Backend -> Permission: IsOwnerOnlyGroup -> Kiểm tra user có role='owner' -> Pass
	Backend -> Database: group.delete() (xóa cascade toàn bộ dữ liệu liên quan)
	Backend -> Frontend: 204 No Content
	Frontend -> User: Chuyển về trang danh sách group, thông báo xóa thành công

--- A.5 DANH SÁCH GROUP CỦA TÔI (ListGroupUser) ---

Use case: Xem tất cả group mà user đang là thành viên.
Actor: User (đã xác thực)

Sequence diagram (text):
	User -> Frontend: Vào trang "Group của tôi"
	Frontend -> Backend: GET /api/group/user/group/ (kèm token, có thể ?search=...)
	Backend -> Database:
		- Lọc Group có members__user=user, members__is_active=True
		- Annotate: member_count, is_member, is_pending
		- select_related created_by__profile
		- Prefetch my_membership (của user hiện tại)
	Backend -> Frontend: Trả về list GroupSerializer (200 OK)
	Frontend -> User: Hiển thị danh sách group

--- A.6 KHÁM PHÁ GROUP (ListGroupSuggestion) ---

Use case: Xem danh sách group gợi ý mà user chưa tham gia.
Actor: User (đã xác thực)

Sequence diagram (text):
	User -> Frontend: Vào trang "Khám phá Group"
	Frontend -> Backend: GET /api/group/explore/ (kèm token, có thể ?search=...)
	Backend -> Database:
		- Lấy tất cả Group, annotate: member_count, is_member, is_pending
		- Chỉ lấy .filter(is_member=False) -> group chưa tham gia
	Backend -> Frontend: Trả về list GroupSerializer (200 OK)
	Frontend -> User: Hiển thị danh sách group gợi ý

-----[USE CASE B] QUẢN LÝ THÀNH VIÊN GROUP---------------------------------------

Chức năng:
	- Xem danh sách thành viên
	- Gửi yêu cầu tham gia
	- Hủy yêu cầu tham gia
	- Xem yêu cầu của tôi
	- Xem tất cả yêu cầu (admin/owner)
	- Chấp nhận/Từ chối yêu cầu (admin/owner)
	- Kick thành viên (admin/owner)
	- Xóa toàn bộ bài viết của thành viên (admin/owner)
	- Thêm/Xóa admin (chỉ owner)
	- Rời group

--- B.1 XEM DANH SÁCH THÀNH VIÊN (ListUserGroup) ---

Use case: Xem tất cả thành viên active trong group.
Actor: Thành viên của group (đã xác thực)

Sequence diagram (text):
	User -> Frontend: Vào tab "Thành viên"
	Frontend -> Backend: GET /api/group/<group_id>/user-list/ (kèm token, ?search=..., ?exclude_role=...)
	Backend -> Permission: IsAuthenticated -> Pass
	Backend -> Kiểm tra: user có is_member permission không? Nếu không -> 403
	Backend -> Database:
		- Lấy GroupMember.filter(group=group, is_active=True)
		- select_related: user__profile, job_role, job_role__department
		- Nếu có exclude_role: loại bỏ member có role_id=exclude_role
	Backend -> Frontend: Trả về list GroupMemberSerializer (200 OK, phân trang)
	Frontend -> User: Hiển thị danh sách thành viên

--- B.2 GỬI YÊU CẦU THAM GIA (SendJoinRequestGroup) ---

Use case: User gửi yêu cầu tham gia group.
Actor: User (đã xác thực, chưa là thành viên)

Sequence diagram (text):
	User -> Frontend: Bấm "Tham gia Group"
	Frontend -> Backend: POST /api/group/<group_id>/send-request/ (kèm token)
	Backend -> Permission: IsAuthenticated -> Pass
	Backend -> Database:
		1. Kiểm tra user đã là member chưa? Nếu rồi -> 400 "Bạn đã là thành viên"
		2. Kiểm tra đã có request pending chưa? Nếu có -> 400 "Đã gửi yêu cầu rồi"
		3. update_or_create: tạo mới hoặc cập nhật request về pending
	Backend -> Frontend: 201 Created / 200 OK (thông báo)
	Frontend -> User: Hiển thị "Đã gửi yêu cầu tham gia"

Activity diagram (text):
	[Bắt đầu] -> Bấm "Tham gia Group" -> Gửi request -> Backend kiểm tra:
		- Đã là member? -> TRUE -> Báo lỗi
		- Đã có request pending? -> TRUE -> Báo lỗi
		- FALSE -> Tạo/Update GroupJoinRequest(pending) -> Thành công
	-> Frontend hiển thị thông báo -> [Kết thúc]

--- B.3 HỦY YÊU CẦU THAM GIA (CancelJoinRequestGroup) ---

Use case: User hủy yêu cầu tham gia đang pending.
Actor: User (đã xác thực)

Sequence diagram (text):
	User -> Frontend: Bấm "Hủy yêu cầu"
	Frontend -> Backend: POST /api/group/<group_id>/cancel-request/ (kèm token)
	Backend -> Permission: IsAuthenticated -> Pass
	Backend -> Database: DELETE GroupJoinRequest (group_id, user, status='pending')
		Nếu không tìm thấy -> 400 "Không tìm thấy yêu cầu"
	Backend -> Frontend: 200 OK (thông báo)
	Frontend -> User: Cập nhật UI, hiển thị nút "Tham gia"

--- B.4 DANH SÁCH YÊU CẦU CỦA TÔI (MyJoinRequestList) ---

Use case: User xem các yêu cầu tham gia group đang pending của mình.

--- B.5 XEM TẤT CẢ YÊU CẦU (AllJoinRequest) ---

Use case: Admin/owner xem tất cả yêu cầu tham gia group.

Sequence diagram (text):
	User -> Frontend: Vào tab "Yêu cầu tham gia"
	Frontend -> Backend: GET /api/group/<group_id>/all-request/ (kèm token, ?search=...)
	Backend -> Permission: IsAuthenticated -> Pass

--- B.6 CHẤP NHẬN YÊU CẦU (AcceptJoinRequest) ---

Use case: Admin/Owner chấp nhận yêu cầu tham gia của user.
Actor: Admin/Owner (đã xác thực)

Sequence diagram (text):
	User(Admin) -> Frontend: Bấm "Chấp nhận"
	Frontend -> Backend: POST /api/group/<group_id>/request/<request_id>/accept/ (kèm token)
	Backend -> Permission: IsAuthenticated, IsAdminOrOwnerGroup -> Pass
	Backend -> Database (transaction.atomic):
		1. Lock row: select_for_update() request (tránh race condition)
		2. Cập nhật request: status='accepted', reviewed_by=admin, reviewed_at=now
		3. update_or_create GroupMember: group=group, user=user, role='member', is_active=True
	Backend -> Signal: accept_join_request_group.send() -> Thông báo cho user được chấp nhận
	Backend -> Frontend: 200 OK
	Frontend -> User: Cập nhật UI, thông báo thành công

Activity diagram (text):
	[Bắt đầu] -> Admin/Owner bấm "Chấp nhận" -> Backend kiểm tra quyền:
		- Không phải admin/owner? -> 403 Forbidden
		- OK -> Transaction bắt đầu:
			SELECT ... FOR UPDATE (lock request)
			UPDATE request SET status='accepted'
			UPDATE OR INSERT GroupMember (user, role='member', is_active=True)
			-> Commit
		-> Gửi signal thông báo cho user
		-> Frontend cập nhật UI -> [Kết thúc]

--- B.12 RỜI GROUP (LeaveGroup) ---

Use case: Thành viên rời khỏi group.
Actor: Thành viên (đã xác thực)

Sequence diagram (text):
	User -> Frontend: Bấm "Rời Group" -> Xác nhận
	Frontend -> Backend: POST /api/group/<group_id>/leave/ (kèm token)
	Backend -> Permission: IsAuthenticated -> Pass
	Backend -> Database (transaction.atomic):
		- Lấy GroupMember của user
		- Nếu role='owner':
			a. Yêu cầu next_owner_id trong request body
			b. Tìm GroupMember của người kế nhiệm
			c. Kiểm tra role của người kế nhiệm phải là 'admin'
			d. Chuyển role='owner' cho người kế nhiệm
			e. Signal: owner_transfer_group.send()
		- Set is_active=False, role='member' -> save()
	Backend -> Frontend: 200 OK
	Frontend -> User: Chuyển hướng ra khỏi group

Activity diagram (text - Luồng Owner rời group):
	[Bắt đầu] -> Owner bấm "Rời Group" -> Form nhập next_owner_id (admin kế nhiệm)
	-> Frontend gửi next_owner_id -> Backend kiểm tra:

Sequence diagram (text):
	User -> Frontend: Bấm vào một option để vote
	Frontend -> Backend: POST /api/group/<group_id>/vote/<vote_id>/option/<vote_option_id>/vote/ (kèm token)
	Backend -> Permission: IsAuthenticated -> Pass
	Backend -> Kiểm tra: User có phải member không? Nếu không -> 403
	Backend -> Database (transaction.atomic):
		- Lấy VoteOption (kiểm tra is_closed=False)
		- SELECT FOR UPDATE: Tìm UserVote hiện tại của user (nếu có)
		- 3 trường hợp:
			a. Chưa vote -> Tạo UserVote mới, increment count của option
			b. Đã vote option này -> Hủy vote (xóa UserVote), decrement count
			c. Đã vote option khác -> Đổi: update option, decrement cũ, increment mới
	Backend -> Frontend: 201 Created (UserVoteSerializer) / 200 (hủy vote)
	Frontend -> User: Cập nhật giao diện (hiển thị % vote)

Activity diagram (text):
	[Bắt đầu] -> User bấm vote vào option
	-> Kiểm tra vote còn mở không (is_closed)? Đóng -> Báo lỗi
	-> Mở -> Kiểm tra UserVote hiện tại:
		1. Chưa vote: Tạo UserVote, count++
		2. Đã vote cùng option: Xóa UserVote, count--
		3. Đã vote option khác: Chuyển option, count cũ--, count mới++
	-> Trả về kết quả -> [Kết thúc]
